1) Deskripsi Aplikasi dan Tujuan

Pada project ini saya membuat aplikasi Android sederhana untuk proses login menggunakan Jetpack Compose sebagai UI dan Room Database sebagai penyimpanan data lokal. Fitur utama yang saya implementasikan adalah input username, input password, tombol login, validasi login ke database lokal, serta menampilkan pesan sukses atau gagal sesuai hasil autentikasi.

Tujuan dari pembuatan aplikasi ini adalah melatih alur dasar autentikasi user di aplikasi mobile, memahami cara kerja database lokal berbasis Room, serta membiasakan pemisahan tanggung jawab kode menggunakan pola arsitektur MVVM agar source code lebih rapi, mudah dipelihara, dan mudah dikembangkan.

2) Arsitektur Aplikasi (Kesesuaian dengan MVVM)

Berdasarkan struktur project yang saya gunakan, implementasi ini sudah mengikuti konsep MVVM secara fungsional. Lapisan View berada pada Compose UI (LoginScreen.kt), lapisan ViewModel berada pada LoginViewModel.kt, dan lapisan Model/Data berada pada Room Database (User.kt, UserDao.kt, AppDatabase.kt) yang diakses melalui UserRepository.kt.

Alur datanya adalah: user berinteraksi di View, lalu View memanggil function di ViewModel, kemudian ViewModel memanggil Repository, Repository mengakses DAO, DAO menjalankan query ke Room (SQLite), hasil dikembalikan ke ViewModel, lalu state UI diperbarui dan ditampilkan kembali ke View. Pola ini sesuai dengan materi MVVM karena UI tidak mengakses database secara langsung.

3) Langkah-Langkah Pembuatan Aplikasi (Detail Tahapan)

  1. Saya menyiapkan project Android Studio bernama Pertemuan 12 dengan package com.example.pertemuan12, lalu memastikan project dapat sync dan build terlebih dahulu.

  2. Saya menambahkan dependency Room, Coroutine, dan lifecycle ViewModel untuk Compose di file app/build.gradle.kts agar aplikasi dapat melakukan operasi database secara asynchronous dan terhubung dengan arsitektur MVVM.

  3. Saya membuat Entity User sebagai representasi tabel users di Room. File ini menjadi definisi struktur data (kolom id, username, password).

  4. Saya membuat DAO UserDao berisi function insert() untuk menambah data user dan function login() untuk validasi username + password menggunakan query SQL.

  5. Saya membuat AppDatabase dengan pola Singleton agar hanya ada satu instance database selama aplikasi berjalan, sehingga akses database lebih aman dan konsisten.

  6. Saya membuat UserRepository sebagai perantara antara ViewModel dan DAO, supaya ViewModel tidak berhubungan langsung dengan layer database.

  7. Saya membuat LoginViewModel untuk menampung logic login, state hasil login, serta function untuk insert data dummy user admin/12345 saat aplikasi pertama dijalankan.

  8. Saya membuat LoginViewModelFactory agar ViewModel yang membutuhkan parameter Repository dapat dibuat dengan benar dari MainActivity.

  9. Saya membangun tampilan LoginScreen menggunakan Compose (input username, input password, button login, dan card status hasil login), lalu menghubungkannya ke ViewModel.

  10. Di MainActivity, saya melakukan inisialisasi AppDatabase → DAO → Repository → ViewModelFactory → LoginViewModel, kemudian memanggil insertDummyUser() dalam LaunchedEffect, lalu menampilkan LoginScreen(viewModel).

5) Penjelasan Detail Setiap Bagian Kode MainActivity.kt

Berikut potongan kode inti MainActivity.kt dan penjelasan per bagian. 

class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContent {
            Pertemuan12Theme {
                Surface(modifier = Modifier.fillMaxSize()) {
                    val database = AppDatabase.getDatabase(this@MainActivity)
                    val userDao = database.userDao()
                    val repository = UserRepository(userDao)
                    val factory = LoginViewModelFactory(repository)
                    val viewModel: LoginViewModel = viewModel(factory = factory)

                    LaunchedEffect(Unit) {
                        viewModel.insertDummyUser()
                    }

                    LoginScreen(viewModel)
                }
            }
        }
    }
}

  1. Inisialisasi Activity dan lifecycle awal: pada onCreate(), saya memulai setup komponen aplikasi saat Activity dibuka pertama kali.

  2. enableEdgeToEdge(): saya mengaktifkan layout agar kompatibel dengan area sistem modern Android (status bar/navigation bar).

  3. setContent { ... }: saya mendefinisikan seluruh UI berbasis Compose, sehingga tidak memakai XML layout tradisional.

  4. Theme dan Surface: Pertemuan12Theme menerapkan tema Material, lalu Surface(fillMaxSize()) menjadi kontainer utama layar.

  5. Rantai dependency data: saya membangun alur AppDatabase -> UserDao -> UserRepository -> LoginViewModelFactory -> LoginViewModel. Tujuannya agar ViewModel menerima data source secara terstruktur sesuai konsep MVVM.

  6. LaunchedEffect(Unit): block ini dijalankan saat composable pertama kali masuk composition. Di sini saya memanggil insertDummyUser() untuk menyisipkan akun awal admin/12345 ke Room Database.

  7. LoginScreen(viewModel): UI login menerima ViewModel sebagai sumber state dan aksi. Saat user klik tombol login, event akan diteruskan ke logic pada ViewModel.

7) Cara Pengujian di Android Studio

  1. Buka project Pertemuan 12 di Android Studio, tunggu proses indexing selesai.

  2. Jalankan Gradle Sync dan pastikan dependency Room, KSP, Coroutine, serta Compose tidak error.

  3. Lakukan Build > Clean Project, lalu Build > Rebuild Project.

  4. Jalankan emulator (minimal Android 7.0/API 24 sesuai minSdk), lalu klik Run app.

  5. Uji tiga skenario: layar awal (belum login), login salah (contoh: admin/11111), dan login benar (admin/12345).

  6. Buka Logcat jika diperlukan untuk memastikan tidak ada crash dan tidak ada exception fatal saat validasi login dijalankan.

9) Kesimpulan

Dari project ini saya memahami bahwa pembuatan fitur login sederhana akan lebih stabil jika menggunakan arsitektur yang terstruktur. Dengan kombinasi Compose + MVVM + Room Database, alur kode menjadi jelas, proses validasi login berjalan asynchronous, dan hasil status login dapat diperbarui secara real-time pada UI melalui state di ViewModel.

Secara keseluruhan, implementasi aplikasi login pada project ini sudah memenuhi kebutuhan tugas: memiliki input username/password, tombol login, validasi kredensial, pesan sukses/gagal, serta penyimpanan data user di Room Database. Struktur file juga mendukung pengembangan lanjutan, misalnya penambahan register, hash password, atau integrasi API.
